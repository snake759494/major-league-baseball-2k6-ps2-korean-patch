# 기술 설명

대상: PS2 북미판 Major League Baseball 2K6 (SLUS-21235), 실행파일 `SLUS_212.35`.

## 디스크 구성

게임 데이터는 `VCDATA/0.`~`VCDATA/3.` 네 파트로 나뉜 VC 아카이브입니다. `0.` 머리에 항목 표(항목마다 12바이트: 종류, 크기, `파트 × 0x80000 + 섹터`)와 파트별 섹터 수가 있습니다. 항목은 LZ 압축 청크(머리 `0xFEEDBEEF`)로 되어 있으며, 압축·해제는 `tools/vc.py`·`tools/lz.py`와 C# 도구 `tools/vcx`가 합니다.

게임은 `0.`의 LBA를 기준으로 **절대 섹터**로 파트를 읽습니다. 그래서 `3.`을 ISO 끝으로 옮기면 경기 로딩에서 멈췄습니다. 지금은 다음처럼 배치합니다.

1. `3.`은 제자리에 두고, 바뀐 항목을 `3.` 끝에 이어 붙여 `3.`을 늘립니다.
2. `3.` 뒤에 있던 IRX, `SLUS_212.35`, `SYSTEM.CNF`(이름으로 여는 파일)는 그만큼 뒤로 밉니다.
3. 항목 표, `3.` 섹터 수, ISO9660 디렉터리, UDF 파일 항목과 앵커를 고칩니다(`tools/isoedit.py`).

결과 ISO 크기는 원본과 같습니다(빈 공간 사용).

## 한글 인코딩

한글 음절은 자주 쓰는 순서로 번호를 매기고 `0x3400 + 번호`(KBASE) 코드로 바꿉니다. 1,144자가 쓰였습니다.

- UTF-16 문자열: 그 코드를 그대로 씁니다.
- ASCII 문자열: 2바이트 `0x80 | 번호>>7`, `0x80 | 번호&0x7F`로 씁니다. 실행파일의 AsciiToUnicode 두 곳(`0x107B10`, `0x27CB50`)이 이 2바이트를 한 글자로 읽게 고쳤습니다.
- UnicodeToAscii(`0x27CB90`)도 반대로 고쳐, 유니코드 한글을 ASCII 버퍼로 옮길 때(팀 목록의 도시·팀 이름 등) 깨지지 않게 했습니다.
- 서식 함수 KSprintf의 `%c`(`0x27B5A0`)는 한글 글자가 오면 아무것도 출력하지 않습니다. 선수 목록의 이름 첫 글자 표시가 한글 반쪽으로 깨지던 문제를 막습니다.

## 동적 한글 글리프 캐시

폰트 텍스처 메모리가 빠듯해(폰트 전체 약 280KB) 한글 1,144자를 미리 그려 넣을 수 없습니다. 대신 `tools/codepatch.py`가 글자 그리기 코드에 캐시를 넣습니다.

- 폰트 범위표에 `(0x7FFF, KBASE, 캐시 블록)` 항목을 더해, 한글 코드는 원래 글리프 조회에서 "없음"이 되게 합니다.
- 폰트 로더(`0x142CA4`)에서 해당 폰트가 쓰는 글리프 세트의 주소를 전역표에 기록합니다.
- 글자 폭(`0x142DE8`)은 한글이면 캐시 블록의 전진폭을 돌려줍니다.
- 글자 그리기(`0x143514`)는 글리프가 없고 한글이면, LRU 슬롯을 하나 골라 세트 데이터의 비트맵을 텍스처 빈칸에 풀어 쓰고 그 슬롯의 UV로 그립니다. 텍스처는 매 프레임 RAM에서 다시 올라가므로 따로 갱신 요청을 할 필요가 없습니다.
- 세트 데이터는 1비트(갈무리11 12px) 또는 2비트(나눔스퀘어 네오 Bold 15·22px)로 저장하고, 캐시 블록의 모드 값으로 풀 때 구분합니다. 폰트 여러 개가 세 세트를 나눠 씁니다(`tools/kfont.py`의 `SETS`, `FONTSET`).
- 새 코드는 어디서도 부르지 않는 함수 영역(코드 동굴)에 넣었습니다.
- 슬롯 수를 늘리려고 폰트 텍스처를 키우면(세로 2배, 4비트) GS 메모리(VRAM)를 더 씁니다. v1.0은 경기 중에도 그려지는 폰트(`Arial_Black_13/15_Italic/17/20`, `font8`)까지 키워, 흐린 날씨(OVERCAST) 경기처럼 VRAM을 많이 쓰는 로딩에서 화면이 깨지며 멈췄습니다. 원본과 폰트를 고치지 않은 빌드는 같은 조건에서 정상이었고, 텍스처를 원래 크기로 두면 EE RAM을 약 400KB 더 써도 정상이었으므로 원인은 EE RAM이 아니라 VRAM입니다.
- v1.1은 `Arial_Black_17`, `Arial_Black_20`, `font8`의 텍스처를 원래 크기로 두고(슬롯 40·27·36개), 나머지 폰트만 키웁니다(슬롯 53~134개). `Arial_Black_13`·`Arial_Black_15_Italic`은 로딩 안내 문구에 쓰여 슬롯이 15~16개면 글자가 섞여 보이므로 키운 채로 두었고, 이 구성은 흐림·바람·낮 조건에서 확인했습니다.

## 문자열 교체

- 실행파일: UTF-16과 ASCII 문자열을 제자리에서 바꿉니다. 원문 길이(0 종료 포함)를 넘지 않는 번역만 넣습니다.
- 데이터 항목: STBL 문자열 표(도움말·퀴즈·이메일 등)는 다시 쓰고, 매뉴얼(MANU)과 기타 UTF-16 데이터는 제자리에서 바꿉니다.
- 선수 데이터(항목 1·140): 0x7C부터 0x138바이트 레코드이며, 이름은 +0, 성은 +0x20(UTF-16, 0 포함 16자)입니다. 한국·일본·대만 선수는 원래 이치로가 저장된 방식대로 이름 칸을 비우고 성 칸에 전체 이름을 넣습니다.
- 이름 첫 글자 서식 `%c. %s` 다섯 곳(`0x4C0528`, `0x4DCAF0`, `0x4E2E99`, `0x53F000`, `0x4EE5D8`의 `%c. %s (%c)`)을 `%c%s`로 바꿨습니다. `%c`가 한글이면 비므로 성만 남습니다.

### 바꾸면 안 되는 문자열

게임이 화면 표시용 문자열을 리소스를 찾는 열쇠로도 씁니다. 다음은 원문으로 둡니다.

- 실행파일 `0x4A9C00~0x4B1400`, `0x4BC780~0x4BFD00` 구간의 한 단어 문자열(구장 노드, 유니폼 부위 이름). 바꾸면 구장·유니폼이 나오지 않습니다.
- 실행파일 ASCII의 한 단어 문자열. 바꾸면 경기 로딩에서 멈춥니다.
- 카메라 `stringtable`(STBL 항목 86~88).
- 팀 데이터의 도시 이름(구장 열쇠). 바꾸면 로딩에서 멈춥니다.
- 아나운서용 이름 목록(PALASTNAMES, SIDLASTNAMES)과 NAMELISTDATA.

## 16:9 와이드 패치

화면비 함수 `0x35D228`은 전역 플래그 `0x8C0360`이 켜져 있으면 16/9(`0x3FE38E39`), 아니면 4/3을 돌려줍니다. 이 플래그는 다른 곳(HUD 배치, 시야 보정 1.5396배 등)에서도 함께 쓰입니다.

플래그는 `0x35CDE8` 함수가 정합니다. 이 함수는 `0x108590`(BIOS `syscall 0x4B` GetOsdConfigParam의 화면 종류)을 불러 값이 2(16:9)이면 플래그를 켭니다. 와이드 패치는 판정 두 명령어를 바꿔 플래그를 항상 켭니다.

| 주소 | 원래 | 바꾼 것 |
| --- | --- | --- |
| `0x35CDF8` | `xori v0,v0,2` (`38420002`) | `addiu v0,zero,1` (`24020001`) |
| `0x35CE00` | `sltiu v0,v0,1` (`2C420001`) | `nop` (`00000000`) |

두 주소의 코드는 원본과 한글판이 같아서, pnach는 파일 이름의 CRC만 다릅니다. PCSX2의 CRC는 실행파일 전체를 32비트 단위로 XOR한 값입니다(`tools/widescreen.py`).
